# Как устроена игра — разобрано по её исходнику

Источник: `reference/game/wurzel_all.js` (1,26 МБ, метка версии `20260908104316`),
скачан 2026-09-09 с `https://s5.ru.molehillempire.com/js/wurzel_all.js`
**без авторизации** — файл статический и открыт всем.

Это не предположения: всё ниже прочитано в коде игры. Файл минифицирован в
несколько огромных строк, поэтому искать в нём надо `tools/probe_game_js.py`
(по смещениям), а не grep.

## Общая картина

- Игра написана на **Prototype.js + Scriptaculous**, всё лежит на самой
  странице `main.php?page=garden`. Фреймов с игрой нет.
- Сад — сетка **17 в ширину**, клетки нумеруются с 1. Шаг строки — 17
  (видно в `berechneFelder` и в `l()`: `E+(17*C)`).
- Клетки в разметке — **`#gardenTile<N>`** (в 2012 было `#b<N>`, схема мертва).
- Режим действия — глобальная `window.mode`: **0 — посадка, 1 — сбор,
  2 — полив**, −1 — ничего. Ставится через `selectMode(mode, a, c, b)`, которая
  кроме `mode` только правит интерфейс.

## Ключевой интерфейс `gardenjs`

| Метод | Что делает |
|---|---|
| `gardenjs.getGrid()` | состояние всех клеток: `{pid, category, water, finished, x, y, sx, sy, …}` |
| `gardenjs.getFieldData(n)` | то же по одной клетке плюс данные продукта |
| `gardenjs.getCurrentGarden()` | номер текущего сада |
| `gardenjs.getElements()` | карта DOM-элементов клеток |
| `gardenjs.action.cache(n)` | **действие над клеткой — то же, что клик мышью** |
| `gardenjs.action.cacheFlush()` | отправить накопленное на сервер |
| `gardenjs.waterAll()` | полить весь сад одним запросом — **осторожно, см. ниже** |
| `gardenjs.harvestAll()` | собрать весь сад одним запросом — **то же** |
| `gardenjs.autoplant.open(cat)` | автопосадка самой игры (на покупаемых «зарядах») |
| `gardenjs.init` | перечитать сад с сервера |

## Как поливать правильно

`gardenjs.action.cache(n)` — это ровно то, что вызывает клик по клетке. Он копит
очередь и отправляет её пачками по 6 (`s=7`, условие `d.length>=s-1`) или по
таймеру 2 секунды (`c=2000`). Итог уходит на `save/wasser.php` с `cid=ajax.token`.

Правильная реализация полива — **с обязательным отсевом до вызова**:

```js
window.mode = 2;
for (var i = 1; i <= 204; i++) {
    if (!canWater(grid, i, now)) continue;   // ← БЕЗ ЭТОЙ СТРОКИ БУДЕТ БЕДА,
    gardenjs.action.cache(i);                //   см. раздел ниже
}
gardenjs.action.cacheFlush();
```

**Почему именно так, а не подделкой кликов.** Вся проверка и весь темп остаются
игровыми: мы не ускоряем ничего искусственно и не обходим ни одного правила —
делаем те же вызовы, что сделал бы человек мышью, только без двухсот движений
рукой. Это же снимает и целый класс ошибок: правило «можно ли полить» не
переписано нами, а исполняется самой игрой.

### Правило «клетку можно полить» (из `cache`, ветка `case 2`)

Клетка поливается, когда **все** условия верны:

- `pid != 0` — на ней что-то растёт;
- `finished > сейчас` — ещё не созрело;
- `water < сейчас − 86400` — полито больше суток назад;
- `category == "v"` — это овощ;
- `pid` не входит в `[238, 253, 263, 285, 459]` — особые растения пропускаются.

Здесь `сейчас` = `Zeit.Client - Zeit.Verschiebung` (время сервера, не браузера).

### ⚠️ Проверку ВСЁ ЖЕ приходится делать у себя — и вот почему

Первая редакция этого файла говорила «свою проверку не писать, `cache()` сделает
всё сама». **Это оказалось опасной ошибкой, вскрытой на живом аккаунте
2026-09-09.** У `cache()` есть ветки, срабатывающие ДО проверки режима:

```js
if (J === "u") { h(R); return false }                       // ПЛАТНЫЙ диалог сноса
if (J === "h" && t[R].weed) { herb.removeWeed(); return false }  // молча полет сорняк
if (data_products[t[R].pid] && data_products[t[R].pid].speedup_reduction && K != 1) {
    p.cacheFlush(); v(R); return false                      // диалог ускорения за деньги
}
```

Режим полива тут ни при чём: действие уже произошло. Слепой обход всех 204
клеток на новом аккаунте, где сад зарос сорняками, открыл игроку окно
«В самом деле убрать? Цена: 2,50 сТ».

Поэтому перед вызовом `cache()` надо самим отсеять всё, что не является обычным
овощем под полив: `category !== 'v'`, `speedup_reduction`, список исключений.
Ошибиться в строгую сторону безопасно (польём меньше), в мягкую — тоже
(`cache()` откажет сама, а на овощах у неё побочных веток нет).

### Мелочи, которые сломают полив
- `cache()` отказывает целиком, если открыт список покупок:
  `$("einkaufszettel").getStyle("display") == "block"`.
- Клетки под многоклеточными растениями считает `berechneFelder`. Собственный
  отсев игры (`m(D)`) защищает от повтора только **пока очередь не сброшена**, а
  сбрасывается она каждые 6 действий. Значит, клетки одного растения надо
  отмечать у себя, иначе на границе пачки растение уйдёт на сервер дважды.

## Как собирать урожай (ветка `case 1` её `cache`)

Разобрано по исходнику и сверено с живой игрой 2026-09-14.

Клетка собирается, когда:

- на ней что-то растёт, и **на каждой клетке растения** (`pid != 0`);
- это обычный овощ. Категорию проверяем САМИ и строго: `'u'` открывает
  платный диалог сноса, `'h'` с сорняком молча полет — обе ветки срабатывают
  ДО проверки режима. `'w'` и `'wd'` игра отвергает сама;
- растение созрело.

⚠️ **Как игра судит о спелости при сборе.** Не по `finished`, а по картинке
клетки: `gardenjs.getElements()[n].b.alt`. Если `alt == 0` (сравнение
нестрогое, там строка), она показывает окно «действительно собрать?» —
недозревший сбор теряет урожай. Замер живой игры: у созревших `alt` равен
строке `"6"`. Поэтому смотрим и `finished`, и `alt`.

`speedup_reduction` сбору НЕ мешает: у неё эта ветка стоит под условием
`K != 1`, то есть на сбор не распространяется.

## Гномы-помощники игры: кто нанят, тот и работает

В полосе `#wimpareaHelper` стоят её собственные помощники. **Нанятый и
ненанятый отличаются классом `off`**, и это единственный надёжный признак —
функция в коде есть у всех одинаково.

| помощник | разметка | `onclick` |
|---|---|---|
| жнец | `.harvest` | `gardenjs.harvestAll()` |
| поливальщик | `.water` (+`off`, +накладка `.locked`) | `research.gotoResearch('waterhelper')` |
| исследователь | `.science` | `research.gotoResearch('plants')` |
| автомат посадки | `#wimpareaAutoplant` | `gardenjs.autoplantOpen('v')` |

Замер живой игры 2026-09-14: **жнец нанят, поливальщик — нет.** Отсюда два
следствия для помощника: полив — самая ценная его работа, а своего жнеца при
нанятом рисовать нельзя (в полосе окажется два жнеца).

**`gardenjs.harvestAll()` зовём ТОЛЬКО когда жнец нанят.** Это её собственная
кнопка, для игрока бесплатная, и один запрос вместо двух сотен. Ненанятый
жнец — значит собираем сами, клетка за клеткой.

## Переключение сада идёт ответом сервера

`my.change = function(n){ ajax.request("ajax",{do:"changeGarden",garden:n},
function(data){ wimparea.reload(); my.init(data); setLocationLine() }) }`

То есть после `waehleGarten(n)` сад НЕ сменился: надо ждать, пока
`gardenjs.getCurrentGarden()` станет `n`.

## Что игра знает сама: `farmchecker`

У неё есть свой обходчик хозяйства — `farmchecker` с таблицей
`farmchecker_types`: `decogarden`, `decogarden2`, `cacti`, `megafruit`,
`bonsai`, `birds`, `bees`, `park`, `snailracing`, `mine`, `biogas`,
`vacation`, `ivyhouse`. По каждому месту в `farmchecker.data` приходят
признаки `ready` / `needcare`, а строка списка ведёт туда же
(`setLocation(...)` + вход места).

**Главных садов в этом списке НЕТ** — а именно там и лежит ежедневная работа.

## ⚠️ `waterAll` и `harvestAll` — не трогать без проверки

```js
my.waterAll = function(){ ajax.request("ajax", {"do":"gardenWaterAll"}, my.init) };
my.harvestAll = function(cb){ ajax.request("ajax", {"do":"gardenHarvestAll"}, …) };
```

Один запрос — и весь сад полит. Выглядит соблазнительно, но это почти наверняка
**платная возможность игры**: в этой серии игр «садовник» покупается за монеты.
Вызвать её вслепую — риск молча потратить чужие монеты.

**Решение: не используем.** Полив делаем через `action.cache`, который заведомо
бесплатен, потому что повторяет обычные клики. Проверять `waterAll` можно
только на тестовом аккаунте и только осознанно.

## Автопосадка

У игры своя: `gardenjs.autoplant.open(category)` → `ajax.request("ajax",
{"do":"autoplantOpen"})` возвращает `loads` (число оставшихся «зарядов») и
список доступных продуктов; `autoplant.plant()` шлёт `{"do":"autoplantPlant",
pid}`. Заряды кончаются и докупаются — в 2012 CupIvan как раз обходил этот
лимит, подменяя окно автомата.

Наш путь для посадки — тот же `action.cache` с `window.mode = 0` и выбранным
продуктом в `window.selected`; заряды при этом не тратятся.

## Сады: сколько их и как переключать

Разобрано 2026-09-09 по `reference/game/wurzel_all.js`.

**Переключение.** Точка входа — `waehleGarten(N)`: закрывает открытые окна,
сбрасывает теплицу и зовёт `gardenjs.change(N)`. Сам `change` — обычный запрос
игры:

```js
gardenjs.change = function (toGardenNo) {
    ajax.request("ajax", {"do": "changeGarden", garden: toGardenNo},
        function (data) { wimparea.reload(); my.init(data); setLocationLine(); });
};
```

Текущий сад — `gardenjs.getCurrentGarden()`. Обратите внимание: `change`
перезагружает полосу помощников (`wimparea.reload()`), поэтому после смены
сада нашу расстановку надо считать заново — этим занят повтор раз в секунду.

**Сколько садов у игрока.** Два поля карты города:

| поле | смысл |
|---|---|
| `citymap.data.garden_count` | сколько садов КУПЛЕНО |
| `citymap.data.garden_max` | сколько бывает всего |

`citymap.buildLocations` рисует сады `1..garden_max` и метит их так: до
`garden_count` — обычная ссылка `waehleGarten(c)`; ровно следующий —
`citymap.buyGardenCommit(c)`; дальше — класс `forbidden` и никакого действия.
Отсюда прямое следствие: **сад открывается только покупкой на сервере**, и со
стороны браузера этого не обойти. Мы кнопку рисуем, а не выдаём права.

**Готовый список садов без запроса к серверу.** У игры есть своя быстрая
навигация `quicknavi`. Её данные — объект вида `{garden1: 1, … garden5: 5,
greenhouse: 1, watergarden: …}`, где ключи `gardenN` и есть купленные сады.
Заполняется из любого ответа сервера:

```js
if (response.quicknavi && quicknavi) { quicknavi.data = response.quicknavi; quicknavi.build(); }
```

Важное для нас: **`data` присваивается ДО `build()`, а `build()` молча выходит,
если на странице нет блока `#quicknavi`**:

```js
quicknavi.prototype.build = function () { if (!this.data || !$("quicknavi")) { return 1 } … }
```

Поэтому бывает так, что игра список садов знает, а кнопок не показывает. Это и
есть случай, из-за которого у игрока «не было пятого сада»: сад куплен,
данные есть, рисовать их некуда. Ровно ту же дыру закрывал Иван в 2012-м
(`functions/gardenButtons.js`) — он тоже сначала смотрел, нет ли у игры своих
кнопок (`indexOf('garten_quick')`), и только потом рисовал свои.

Крайний случай — `quicknavi` вообще нет. Тогда спросить можно запросом
`{"do": "citymap_init"}`: это чтение, его же делает `citymap.init()` при
открытии карты. Мы шлём его ТОЛЬКО по нажатию — панель сама на сервер не ходит.

**Картинки для кнопок** — те же, что у Ивана: `pics/garten/gartenN.jpg`, 16×16,
живы на `wurzelimperium.wavecdn.net` (проверено 2026-09-09).

## Рынок и торговая палатка

Разобрано 2026-09-10 на живой игре (тестовый аккаунт владельца, s5). В `wurzel_all.js`
рынка НЕТ — это отдельные серверные страницы со своей разметкой и формами.

**Три уровня кадров.** Помощник живёт в верхнем окне и внутрь кадров не
вставляется (`window.top !== window.self` — выходим). Но кадры того же узла,
поэтому из верхнего окна до них можно дотянуться через `contentWindow` —
так и работаем, не заводя второй точки вставки.

```
верхнее окно  main.php?page=garden
  └─ #stadtframe   stadt/index.php?karte=1     ← zeigeStadtMain(1)
       └─ #shopframe  stadt/markt.php…         ← zeige('markt')
                      stadt/marktstand.php     ← «твоя палатка»
```

`zeige(что)` живёт в ВЕРХНЕМ окне и подменяет `#shopframe`:
`markt` → `markt.php?page=1&order=&v=`, `shop1…shop5` → `shop.php?s=N`.
Выход из города — `stadtVerlassen()`.

**Рынок `markt.php`** — чужие предложения. Формы `form_markt_buy`
(поля `buy_menge`, `buy_max`, `buy_id`, `buy_price`, `markt_buy_nr`, `page`,
`order`, `v`, `filter`) и `form_markt_anull` (снять своё). Ссылки вида
`markt.php?filter=1&page=1&order=p&v=<pid>` — предложения по одному товару,
`order=p` сортирует по цене. Комиссия рынка — 10 % (число из кода Ивана).

**Палатка `stadt/marktstand.php`** — где продают. Товары на складе разложены
как `<div class="v<pid>" id="p<pid>" title="морковь"><input type="hidden"
id="anzahl_<pid>" value="163"></div>`, то есть и что есть, и сколько.
Нажатие открывает «ценник», форма продажи:

| поле | смысл |
|---|---|
| `p_id` | какой товар |
| `p_anzahl` | сколько единиц (проверка `checkInput(this, 1, produkt_max)`) |
| `p_preis1` | цена, целая часть |
| `p_preis2` | цена, дробная часть |
| `prepare_markt` | всегда `true` |

**ГЛАВНОЕ: игра сама публикует допустимый коридор цен.** На странице палатки
лежит `price_regulation_data` — по одному `{min, max}` на товар:

```js
price_regulation_data = {"2":{"min":0.02,"max":0.24},"6":{"min":0.01,"max":0.18},…}
```

Цену вне коридора игра не примет. Отсюда правило для нас: цену **брать из этой
таблицы**, а не выдумывать, и в неё же зажимать любую расчётную.

**ПРОДАЖА ИДЁТ В ДВА ШАГА — доведено до конца на живой игре 2026-09-10:**
одна морковь выставлена и снята обратно.

| шаг | что отправляем | что приходит |
|---|---|---|
| 1 | `form_prepare_markt` (`p_id`, `p_anzahl`, `p_preis1`, `p_preis2`, `prepare_markt=true`) | та же страница палатки, но с блоком `#gebuehrenDiv`: комиссия 10 % — и второй формой |
| 2 | `form_verkaufe_markt` — **нажатием** кнопки `verkaufe_markt` со значением `O.K.` | палатка с новым предложением; запас уменьшился |

Три вещи, каждая из которых уже сломала заход:

1. **`form.submit()` на шаге 2 не годится.** Значение кнопки отправки
   браузер посылает только при настоящем нажатии; без него сервер отдаёт
   обычную палатку и сделка молча не состоится. Проверено: склад не
   изменился, предложение не появилось.
2. **Пустое `p_anzahl` игра понимает как «ВЕСЬ ЗАПАС».** Код передал одну
   штуку, поле к моменту отправки оказалось пустым — и на комиссию ушли все
   163 моркови. Денег это не стоило только потому, что шаг 2 отдельный.
   Отсюда правило: значение проставлять дважды (сразу и перед отправкой) и
   ПОСЛЕ шага 1 сверять, что игра поняла то самое количество.
3. **На странице комиссии ценника НЕТ.** `#preisschild` там остаётся, а полей
   `produkt_anzahl`, `produkt_preis1`, `produkt_preis2` внутри него нет.
   Значит «есть `#preisschild`» ещё не значит «палатка готова принять
   предложение»: если игрок подготовил сделку и ушёл, кадр остаётся на этой
   странице. Лечится перезагрузкой палатки — уход с неё и есть отказ от
   неподтверждённой сделки.

**Снятие предложения** — иконка в `#angeboteDiv` с `onclick="anull('<номер>')"`;
запас возвращается на склад полностью (проверено).

**Товар нажимается через Prototype**, а не атрибутом:
`$("p6").observe("click", zeigePreisschild.curry($("p6"), true))`. Обычный
`element.click()` до обработчика доходит. `zeigePreisschild` ОЧИЩАЕТ поля —
заполнять только после нажатия.

**Осторожно с методами массивов.** На странице игры живёт Prototype.js, он
подменяет `Array.prototype.filter` своей версией с другими аргументами:
`a.filter(function(v,i,a){…a.indexOf…})` падает «Cannot read property indexOf
of undefined». В коде, который работает на странице игры, — обычные циклы.

**Чем это отличается от приёма Ивана.** У него (`autoUpdateMarketPrice.js`)
скрытый кадр сам обходил рынок по всем овощам с паузами 5–9 секунд — работа без
игрока, запрещена АС-7 и со стороны сервера выглядит ботом. Нам обход не нужен:
цена одного товара берётся одной загрузкой `markt.php?…&v=<pid>` и только по
нажатию.

**Валюта.** сТ — садовые талеры, ОБЫЧНЫЕ игровые деньги: рынок игроков торгует
в них. Премиальная валюта игры — coins, её покупают за настоящие деньги
(`newsToBuycoins` в городе). В исходнике слово `coins` встречается 652 раза, из
них ~247 в окружении «купить/цена/стоимость» и ~13 — «выигрыш/бонус».
**Создать coins со стороны браузера нельзя, и мы этого не делаем.**

## Быстрая навигация: какие бывают места и чем их открывать

Разобрано 2026-09-10 по `quicknavi.prototype.build` и подтверждено на живой
игре. Игра держит карту «ключ места → как его открыть»; перед входом она зовёт
`setLocation('<ключ>')`, иначе не будет знать, где игрок находится.

| ключ | подпись игры (`location_name`) | как открыть |
|---|---|---|
| `garden1…7` | Сад | `waehleGarten(N)` |
| `greenhouse` | Теплица | `zeigeGewaechshaus()` |
| `watergarden` | Водный сад | `watergarden.open()` |
| `herbgarden` | Травяной сад | `herb.open()` |
| **`megafruit`** | **Выращивание грибов** | **`initMegafruit()`** |
| `bonsai` | Школа бонсай | `bonsai.init()` |
| `bees` | Пчёлы | `bees.init()` |
| `birds` | Птичья почта | `birds.init()` |
| `park` | Городской парк | `park.init()` |
| **`snailracing`** | **улиточные бега** | **`snailracing.init()`** |
| `mine` / `biogas` / `vacation` / `ivyhouse` / `museum` | ещё не переведены | `<ключ>.init()` |
| `city1` / `city2` | Дачное / Огородное | `zeigeStadtMain(1)` / `(2)` |
| `guild` | Гильдия | `gildejs.open()` |

**Что у игрока ЕСТЬ — только в `quicknavi.data`.** Ключи там перечисляют
доступное; значение `0` игра считает «нельзя» и рисует у себя иконку классом
`no-entry` без действия. Функции входа (`initMegafruit`, `snailracing`) есть в
коде у ВСЕХ — их наличие ничего не доказывает. Поэтому кнопку рисуем только
когда `quicknavi.data[ключ]` истинно: нажатие на неоткрытое привело бы в
никуда или в платное окно (у грибов для этого есть `#megafruit_teaser_link`).

**Иконки — её собственные, из её же таблицы стилей** (`#<ключ>_quick`),
16×16, живы на хранилище:

| место | картинка |
|---|---|
| грибы | `pics/pilzzucht/pilzgarten_premiumwahl.jpg` |
| улитки | `pics/snailracing/SchnellreiseIcon_02.gif` |
| сады | `pics/garten/garten<N>.jpg` |
| город | `pics/garten/garten_stadt.jpg` |

Сами иконки игра рисует не картинками, а фоном по правилу
`#quicknavi .quicknavi-icon` — то есть вне блока `#quicknavi` её стили не
применятся, и путь к файлу надо брать из правила, а не надеяться на класс.

## Что ещё предстоит разобрать
- `regal` (50 ключей) — полка с семенами: `getProductInfos`, `getCount`,
  `getCategory`, `getInfos`, `isEmpty`, `decrementCount`. Нужен для посадки.
- Список симпов и расчёт выгоды — в 2012 перехватывали `ajax.request` с
  `url == "verkaufajax"`, `data.do == "getData"`. Проверить, жив ли путь.
- `data_products` (522 ключа) — справочник овощей: цены, время роста, размеры.
  Основа расчёта рентабельности.
